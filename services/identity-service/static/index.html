Identity Service

OAuth2 clients, scopes, and this platform's active signing keys.

No bearer token on this page, anywhere -- and that's not a design choice, it's a real gap. Unlike every other /ui page in this platform, nothing here is behind a scope check: browsing clients and registering a brand new one both need zero authentication in the current backend. Confirmed live, not assumed -- a caller with no Authorization header at all can self-grant any allowed_scopes string it likes to a client it creates. This is a genuine backend security gap on this reference platform (not fixed here -- it's a trust-model decision, not a UI change). Treat this page as read-only-in-spirit even though the write actually works.
